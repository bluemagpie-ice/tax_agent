# Research Agent 本地运行、操作与架构指南

## 启动服务

在 Windows PowerShell 中进入项目根目录。首次安装依赖可参考 [项目快速开始](../README.md#快速开始)。

```powershell
.\.venv\Scripts\python.exe -m uvicorn web.main:app --host 127.0.0.1 --port 8000
```

启动后，在浏览器打开 [本地页面](http://127.0.0.1:8000)。在页面的「模型配置」中填写模型 ID、API Key 和 Base URL。政策知识库的连接方式见项目快速开始。使用外部模型、向量服务或搜索服务时，相关输入可能发送给服务提供方。练习时请使用公开资料或已泛化的业务事实。

## 从研究问题到保存案例

1. 点击「普通问答」旁的 **Research 研究**，新建任务并输入咨询问题。开启官网检索后，系统会尝试搜索并读取官方网页。关闭时，任务使用已配置的政策知识库。
2. 遇到待确认问题时，可以集中补充，也可以保留未知并继续。默认最多追问两轮。进度区显示当前阶段，以及已有初步证据的子问题数。刷新页面或重启服务后，可从任务选择器重新打开已保存的任务。
3. 展开报告里的政策来源，核对实际读取的内容和来源信息。缺失的日期、地区或效力信息会保留为未知或待核实。可编辑报告、删除不准确的分析、按意见退回研究，或点击「确认此版本定稿」。定稿记录用户对当前版本的确认，专业复核另行记录。
4. 定稿后，点击 **提取候选案例并预览**。系统直接从报告映射字段，这一步无需额外调用模型。预览仅对部分常见信息做泛化处理，请逐项检查全文和来源，手动删去可识别客户的信息。确认保存并发布后，该版本才进入个人案例库。取消会放弃候选案例。
5. 在个人案例库中可手工录入案例、确认保存、发布、修改、撤回、删除和查看版本记录。修改会生成新草稿，旧版本会立即退出后续检索，新版需重新确认发布。专业复核记录包括操作人和备注，当前版本仅记录声明，专业资质由使用者核实。

停止流式执行后，已完成的步骤会保存，之后可恢复。已经发出的外部请求可能继续运行到超时。

## 工作流与数据保存

Research 使用独立的 LangGraph 工作流。方括号表示遇到缺失事实时才进入的步骤。

```text
理解问题 → [准备追问 → 暂停等候补充 → 重新理解问题]
→ 召回和比较案例 → 制定计划 → 检索政策 → 计算 → 评估证据
→ [发现缺口时补充检索并重新评估]
→ 生成报告 → 暂停等待复核 → 确认定稿 / 修改报告 / 退回研究
```

没有命中案例的单问题任务采用一步计划，节省一次规划模型调用。多问题任务最多规划四步，并检查步骤之间的依赖关系。默认上限为三轮检索、一次重规划、16 次工具调用、14 次模型调用，以及按字节保守估算的 100,000 token 预算。这些是执行上限，实际用量以服务方返回的数据为准。可按任务或实验调整代码及配置中的预算。检索工具以只读方式运行。系统检查来源字段和各子问题的证据覆盖情况，政策效力和业务适用性留待人工判断。

- **研究任务和报告**保存在现有业务 SQLite 数据库的新表 `research_tasks` 和 `research_reports` 中，使用 SQLAlchemy Core。任务 JSON 保存事实、未知信息、阶段、计划、证据、执行轨迹、报告和调用记录。每个报告版本保存为独立快照。
- **断点恢复**复用 AsyncSqliteSaver。线程 ID 带有用户范围和 `research:<task_id>` 标识，与普通对话 ID 分开。Research 的上下文来自研究任务本身。任务归属由登录身份决定，调用方填写的用户 ID 无法改变归属。
- **并发控制**使用版本号校验，以及默认 10 分钟、可续期的执行占用凭证。过期版本的请求和同一任务上的重叠操作会被拒绝。执行进程异常退出后，若任务仍被占用，可等凭证到期再尝试恢复。恢复时会保留已完成的步骤，未保存结果的外部调用可能重跑。
- **个人案例库**使用 `research_cases`、`research_case_versions` 和 `research_case_events` 三张表。当前发布版本、保存确认、专业复核分别记录。系统先按业务事实和条件进行关键词召回，再比较税种、地区、所属期和业务类型。地区或所属期不同的案例仍可能作为比较材料。报告把历史材料列为线索，研究流程会继续检索政策。案例保存在 SQLite 中，与公共政策的 Qdrant 集合隔离。

删除案例会清除版本内容，并保留最少的删除标记和操作记录。删除普通对话对已发布案例无影响。既有研究报告可能仍保留审计所需的历史案例引用快照。若需要清理曾提交给外部模型的内容，需按服务提供方的留存规则另行处理。

数据库初始化可重复执行，当前迁移通过新增表保留现有数据。未来若需不兼容的结构变更，应新增带版本的迁移。普通问答继续使用原有 API 字段和路由。

## 新增 API

- `POST /api/research/tasks` 创建任务，参数包括 `query`、`web_search`、`use_cases`。
- `GET /api/research/tasks` 列出当前用户的任务，`GET /api/research/tasks/{id}` 查看单项任务。
- `POST /api/research/tasks/{id}/run` 或 `POST /api/research/tasks/{id}/stream` 执行或恢复任务，需传入当前 `revision`。
- `POST /api/research/tasks/{id}/review` 支持补充事实、确认、修改、退回研究，对应 `clarify`、`confirm`、`revise`、`research_again`。报告操作需传入 `report_version` 和 `revision`。
- `GET /api/research/tasks/{id}/reports` 查看各版本报告快照。
- `GET /api/research/tasks/{id}/case-preview?generalize=true` 预览已定稿报告的候选案例。
- `GET /api/research/cases` 列出案例，`POST /api/research/cases` 创建案例，`POST /api/research/cases/{id}` 执行需校验版本号的案例操作。
- `GET /api/research/cases/{id}/history` 查看当前用户有权访问的案例版本及审计记录。

## 演示与验证

可用一条模拟的设备采购咨询演练。先研究并打开政策来源，复核报告，定稿后预览、泛化并保存案例。再提交一条设备用途或所属期不同的咨询，查看历史案例及关键差异，确认本次任务也检索了政策。实际咨询时，历史结论的效力与适用性须按新任务重新核对。

```powershell
.\.venv\Scripts\python.exe scripts/run_tests.py tests/test_research.py tests/test_research_cases.py tests/test_research_eval.py -q
node --check web/static/research.js
```

测试使用临时 SQLite、临时检查点，以及脚本模拟的模型和工具。测试数据与正式 Qdrant 集合隔离。`node tests/test_research_ui.js` 使用模拟网页元素检查模式隔离、流式消息分段、确认发布及切换身份后的状态清理。真实浏览器交互和无障碍功能需单独验收。Windows 测试启动脚本将临时目录权限调整限定在本次测试专用目录。

A/B/C 分组、原始数据导出、人工评分和探索性配对分析见 [评测及数据导出说明](../eval/research/README.md)。

## 当前功能边界

完整的政策时效推理、更广的官方来源覆盖、案例语义检索、企业级鉴权和并行检索留待后续。当前研究计划内的检索按顺序执行，并受预算限制。

A/B/C 共用现有增值税计算工具的受限路径。该路径用于一般纳税人，须明确提供销售额、税率、可抵扣进项税额和销售额是否含税。每个数值参数都与用户原话核对，并处理金额及百分比换算。其他复杂计算继续走普通计算路径。计算工具的内置默认参数仅供计算流程使用，政策依据须另行核实。

引用检查用于确认报告能追溯到读取过的材料。条款如何解释、是否有效、能否用于这笔业务，仍需人工判断。原始调用记录可能包含问题与来源文本。请使用公开或已泛化的数据，限制本地数据库访问，并在部署前确定留存期限。

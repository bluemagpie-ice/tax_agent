# 税务 Agent（TaxAgent）

一个面向中文财税场景的 **多 Agent + RAG 智能问答系统**：接收用户税务咨询，自动识别意图、调度多个专业子 Agent 协作，结合本地知识库检索与联网实时检索给出带依据的回答，并具备跨会话记忆与多租户隔离。

## 技术栈

- **Web 层**：FastAPI + Jinja2（SSE 流式对话）
- **编排**：LangGraph（StateGraph + SQLite checkpointer 多轮持久化）
- **LLM**：智谱 GLM（`langchain-openai` 兼容接口）
- **向量库**：Qdrant（云端）+ BM25 词法 + Neo4j 图（可选），RRF 融合
- **Embedding**：SiliconFlow（`BAAI/bge-large-zh-v1.5`，1024 维）
- **存储**：SQLite（SQLAlchemy 业务表 + 原生键值存储层）
- **文档解析/OCR**：Docling、PyPDF、PaddleOCR
- **联网检索**：Bing（财政部/税务总局定向，无需搜索 API Key）

## 核心能力

1. **自主决策 + 多 Agent 协作**：主图由 LLM 选择工具、观察结果、再次决策；专业筹划/申报/发票/合规可走原有混合意图路由与 6 类子 Agent，保留原专业路径。
2. **RAG 检索**：文档解析 → 分块（含法律条文结构化切分）→ 向量化 → 多路召回（语义 + 词法 + 图）→ RRF 融合，回答带标题/文号/发布机关/生效日期等引用溯源。
3. **精确税务计算**：增值税/企业所得税/个人所得税/附加税费/印花税由纯函数硬编码公式计算（非 LLM 脑补），LLM 只做参数提取与解释。
4. **跨会话记忆**：工作记忆 + 会话摘要压缩 + 用户画像（跨会话聚合），按租户物理隔离，乐观锁防并发覆盖。
5. **自主联网检索**：勾选联网后，模型按需求选择搜索或读取网页正文；普通问候可不调用工具，来源以实际检索结果为准。
6. **政策自动更新**：本地目录 / 国家税务总局法规库 / 财政部爬取 → 去重 → 增量入库；政策页面支持手动扫描、管理源、调整间隔与查看报告。
7. **离线评估框架**：内置 23 条评测集，量化意图准确率 / 关键词召回率 / 拒答正确率。
8. **增量索引**：上传新文档只向量化新增块，不重算全库。
9. **人工审批**：导出申报辅助 JSON 草稿前，图暂停并展示预览；批准后才生成可下载内容，拒绝直接终止。文件随会话检查点保存，删除对话时一起清理；目前不支持官方可提交申报表或发送邮件。
10. **交互追问**：关键计算条件不足时，模型调用追问工具暂停；用户在原会话补充信息后继续，重启后仍可恢复。
11. **自我校验**：生成草稿后独立审校，复算已调用的计算器；错误有依据地修正，正常答案逐字保留，审校失败明确标记未核验。模型审校不能保证税务事实准确，静态计算器备注不等于现行法规依据。
12. **计划执行**：复杂依赖任务可由模型制定最多 4 步计划，按顺序填参、执行并检查参数与结果结构；失败最多重规划一次，已验证结果保留。单步问题不强制规划。

## 快速开始

Windows PowerShell，先安装 Python 3.12，并进入项目根目录：

```powershell
# 1. 创建环境并安装已有功能所需依赖
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 2. 首次配置；已有 .env 时跳过复制，避免覆盖密钥
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# LLM 可在首页 ⚙ 弹窗填模型 ID、API Key、Base URL。
# RAG 还需在 .env 填 Qdrant 地址/密钥、VECTOR_SIZE，并配置 Embedding。

# 3. 启动服务（--host / --port 可按需调整）
.\.venv\Scripts\python.exe -m uvicorn web.main:app --host 127.0.0.1 --port 8000
# 打开 http://127.0.0.1:8000

# 4. 运行测试；以本次输出为准，外部服务的 Mock 测试不代表真实端到端通过
.\.venv\Scripts\python.exe -m pytest tests/ -q

# 5. 离线评估（意图路由，无需 LLM/Qdrant）
.\.venv\Scripts\python.exe -m eval.run_eval --mode intent
```

## 配置与鉴权

- 模型/Embedding 配置：首页侧栏 ⚙ 先选 GLM / DeepSeek / Kimi / Gemini / 自定义，自动填充地址；检测连接与获取列表均请求该地址的 `/models`，返回 ID 填入可自由输入的 datalist。自定义不限模型 ID。保存到 `data/config.json`，下次对话使用新客户端，右上角显示所选模型；只展示同一端点已获取的模型，不把 GLM 模型混入 Gemini 列表。页面重开后可重新获取列表。
- 同一模型端点 API Key 留空保留；切换端点需填写对应密钥，或使用匹配提供商的 `GEMINI_API_KEY` / `GOOGLE_API_KEY`、`DEEPSEEK_API_KEY`、`KIMI_API_KEY` / `MOONSHOT_API_KEY`、`GLM_API_KEY` / `ZHIPU_API_KEY` 环境变量。不会把旧提供商密钥发往新 URL，模型列表检测不会保存配置。Gemini 使用 [官方 OpenAI 兼容地址](https://ai.google.dev/gemini-api/docs/openai) `https://generativelanguage.googleapis.com/v1beta/openai/`；列表可访问不保证每个 ID 都能用于对话或向量化，仍需实际调用验收。
- Qdrant 面板查询已保存地址的集合状态与精确点数（本项目每点一个向量），估算 float32 向量正文空间；可保存 Cloud 或自建 HTTP(S) 地址与密钥，新地址空密钥适用于无鉴权实例。地址切换不迁移文档或向量。可设置向量数量预警上限，达到 80% 显示橙色提示；0 表示不设数量上限。Cloud 地址在未设数量上限时，以[免费档 1 GiB RAM](https://qdrant.tech/cloud/)作参考，按[向量正文 × 1.5 的粗估](https://qdrant.tech/documentation/search-tuning/when-your-collection-outgrows-ram/)达到 80% 预警；自建地址不套用免费档参考。实际免费限制按资源，并无统一向量数上限；估算不含 payload、其他集合，不是实际用量、配额或账单，付费集群应自定数量上限。配置仍为服务级设置，适用于本地演示。
- 鉴权：请求头 `Authorization: Bearer <token>`。
  - `AUTH_USER_TOKEN`：普通用户（默认 `test_token_123`）
  - `DEVELOPER_TOKEN`：开发者，可使用政策面板（回退 `AUTH_ADMIN_TOKEN` / `admin_token_456`）；普通演示用户也可打开模型配置弹窗。
  - 仅演示用途，生产环境请替换为真实鉴权。

## 业务场景与演示

面向中小企业财税人员和税务咨询顾问，解决政策资料分散、计算口径易混淆、重复咨询缺少上下文的问题。定位为资料检索与计算辅助，正式申报由财税人员核对政策原文和业务条件。

1. 知识问答：配置 LLM、Embedding 和 Qdrant，启动时预置 Markdown 自动入库；若启动时尚未配置 RAG，配置后上传 `knowledge/presets/` 中的文件，再问“什么是进项税”。
2. 计算闭环：问“我是增值税一般纳税人，本月不含税销售额 100000 元，税率 13%，进项税额 8000 元，帮我算应纳税额”。计算模块在这些明确假设下输出 5000 元，LLM 负责参数提取和解释。
3. 联网闭环：勾选“联网检索最新政策”，问“请搜索国家税务总局增值税法的官网链接并读取一篇原文”；主图让模型自行选择搜索、读取和停止顺序，最多 5 轮决策工具补充，每轮最多 3 个工具，资料总量也有预算。没有勾选时不开放联网工具。无需把本轮资料写入 Qdrant；无匹配或网页读取失败会给模型明确结果，回答须区分摘要与原文。Bing HTML 无官网结果时尝试 RSS，仍可能受网络和搜索质量影响。
4. 记忆演示：同一会话继续提问，再重启服务，从侧栏打开历史；会话保存在本地 SQLite，记忆只保存原始问题及最终回答，不反复存入检索背景。

首页通过 SSE 显示处理状态、等待期间发送保活事件；主图完成审校后发送最终正文，避免错误草稿先展示。参数提取、多 Agent 中间结果不作为正文输出，原流式 API 保留。日志记录首字与总耗时；会话标题直接截取原始问题，避免额外等待一次模型调用。审批和追问会显示独立面板，重新打开历史会话可恢复待处理状态。

回复期间可切换侧栏对话或新建对话：每个会话独立保存请求、流式消息、草稿、上传文件与审批状态；可同时向另一对话发问。侧栏绿色旋转圆点表示正在回复，发送/停止按钮只控制当前对话。完成后保留完整答案，服务端仍按原流程持久化。关闭浏览器或离开首页会断开尚未完成的请求；切换会话不离开页面。切换身份或删除正在回复的对话前，需要先停止相关回复。

前端并发状态回归使用 Node 内置模块，不安装额外包：`node tests/test_conversation_ui.js`；覆盖双会话并发、后台消息隔离、切回完整结果、动画消失及只停止当前会话。

无需新增依赖；模型需支持 OpenAI 兼容的 tool calling。使用同一个会话完成以下交互，后台 `[workflow]` 日志及受鉴权的 `GET /api/conversations/{session_id}/workflow` 可查看实际节点、工具和分支证据（不输出工具参数或正文到日志）。

| 任务 | 演示输入 / 操作 | 预期证据 |
| --- | --- | --- |
| 1 自主工具 | 勾选联网后问官网链接；另开会话问“你好” | 前者 `decision→tool→decision`，后者 `tools:[]`；上限退出用可控模型测试 |
| 2 审批 | “生成一个申报辅助JSON草稿，内容是待人工核对的增值税示例” | `approval_prepared` 暂停；批准后 `approval→export`、可下载；另开会话拒绝，无文件生成 |

| 5 计划 | “先计算增值税，再按实际缴纳额计算市区附加税”；给上述参数和消费税0 | `planner→executor(step0)→executor(step1)`；非法参数触发一次 `replanner` |

## 文档管理与删除演示

- 首页 📄 打开“我的文档”，可预览解析文本、按全局/会话筛选并删除。全局文件只用于上传者的所有对话；会话文件只用于指定对话，删除对话时一起清理。文件保存在本机 `uploads/`，分块保存在本地 JSON/SQLite 和 Qdrant Cloud。
- 上传前可选“仅当前对话”或“我的所有对话”；空对话也可先上传。普通用户看不到管理员的系统资料，系统资料用于 RAG 检索，并未微调模型。
- 历史无归属文档不自动认领，先隔离；管理员在文档页勾选管理选项可查看和删除。管理员可“同步云端清单”发现仅存于 Qdrant 的资料；云端只有分块时预览分块文本，无法还原已丢失的原文件。
- 删除按 `file_id` 清理 Qdrant 向量和文本 payload，等待完成并检查剩余数量，再清理本地分块、原文、SQL 记录、检索缓存与相关会话上下文。失败保留 `delete_failed` 记录，可重试；上传失败保留隔离记录，也可删除后重新上传。
- 管理员删除预置资料时保留仓库原始素材，但记录停用，重启不会自动重新入库。历史聊天仍可浏览，删除资料相关的旧上下文不再参与后续回答。
- 演示鉴权仍是两个 Token；实际多人部署需接入真实账号。浏览器每个标签页使用当前访问 Token，不提供匿名文档查询。

### 上传与 OCR 环境

单文件上限 **20 MiB**；空文件返回 400，超过上限返回 413，均不写入管理目录或创建文档记录。上传成功保留原 `file_name` 字段，并返回 `file_id`、`filename`、`size`（字节）、`mime_type`、`url`；`url` 是需携带访问 Token 的解析正文预览接口，不是公开的原件下载链接。

图片与扫描 PDF 需要补齐可选 OCR 环境。以下组合已在 Windows / Python 3.12 / CPU 上实测：

```powershell
.\.venv\Scripts\python.exe -m pip install paddlepaddle==3.3.0 -i https://www.paddlepaddle.org.cn/packages/stable/cpu/
.\.venv\Scripts\python.exe -m pip install paddleocr==3.7.0 pdf2image==1.17.0
# 扫描 PDF 另需安装系统 Poppler，并把其 bin 目录加入 PATH。
# 重开终端后，以下两个命令都应可运行：
pdfinfo -v
pdftoppm -v
```

参考 [PaddlePaddle Windows 官方安装说明](https://www.paddlepaddle.org.cn/documentation/docs/install/pip/windows-pip_en.html) 和 [PaddleOCR 安装说明](https://paddlepaddle.github.io/PaddleOCR/main/version3.x/installation.html)。首次 OCR 会联网下载官方模型，需等待下载完成；本机已下载方向识别、检测、识别模型。关闭当前 CPU 组合不兼容的 MKL-DNN 推理选项，保留 OCR 功能。OCR 无正文、初始化失败或扫描页处理失败会明确报错并隔离文档，不会把“识别失败”当正文向量化。

迁移先用 `PRAGMA table_info` 检查，再按需 `ALTER TABLE ADD COLUMN` 补齐发布日期、URL 和来源名称，兼容重复启动；[SQLite ADD COLUMN](https://www.sqlite.org/lang_altertable.html#altertabaddcol) 没有 `IF NOT EXISTS` 语法。旧记录可从快照或文件名恢复日期；无法确认则显示“未知（未提供）”，不以检测时间冒充发布时间。本地文件无网页链接，不伪造 URL；旧记录仅存网站文章 ID 时无法凭空还原原文地址，下次同正文扫描会补齐可获取的元数据，仍去重且不改变旧哈希、快照和检测时间。

## 简单数据与选型取舍

2026-10-08 本机离线运行：意图命中 **23/23**，整组路由耗时约 **22 ms**。这是小型内置样本上的路由指标，不是税务答案准确率，也不包含网络或 LLM 延迟。真实 Bing 定向检索“增值税”单次约 **0.57 秒**，返回 1 条税务局域名结果；网络环境和查询词会影响结果数量与延迟。

2026-10-09 真实 GLM-5.3 同题单次对比：“你好，请用一句话介绍你能帮我做什么。”从首字 15.36 秒/总计 16.55 秒降至 2.73 秒/5.16 秒；同时改了首轮复用与推理档位，未经重复采样或负载控制，不能归因到单项或保证每次相同。真实联网对话完成一次（37.20 秒，含搜索工具与来源）；增值税示例完成一次（21.36 秒，回答含计算结果 5000 元）。

成本按调用次数估算：主图普通知识问答通常 1 次决策 + 1 次审校；精确简单问候用本地检查，免额外审校调用。单税额通常 1 次工具决策 + 1 次结果解释 + 1 次审校；复杂计划另加 1 次规划及每步骤 1 次填参，重规划会再增加调用。原专业子 Agent 的参数提取/解释与多 Agent 汇总仍保留。网页工具会增加模型轮数；页面标题不调用模型。新增校验与规划会增加延迟，金额取决于实际价格和 token，本项目未测算真实费用。

保留现有 FastAPI、LangGraph、Qdrant 和 SQLite：SQLite 支持本地检查点与审批恢复；主图增加必要的决策和校验节点，专业路径继续使用原关键词/相似度路由，只有多 Agent 输出时汇总。现阶段不增加队列、缓存、微服务或额外编排框架，以降低部署与讲解成本。

独立子 Agent 最多两个并发，结果按路由顺序汇总；每个专业 Agent 已能检索资料，避免为了“进项税/所得税”等名词重复调计算和知识 Agent。参考 [LangGraph 流式输出](https://docs.langchain.com/oss/python/langgraph/streaming)、[Dify 并行分支](https://dify.ai/zh/blog/accelerating-workflow-processing-with-parallel-branch) 的做法，复用现有框架；并发会提高瞬时调用量，不保证所有问题都更快。

GLM-5.3 的最终答复使用 `reasoning_effort=low` 减少默认深度推理的等待，保留思考和工具能力；其他模型不发送此选项。依据 [GLM-5.3 官方参数文档](https://docs.z.ai/guides/llm/glm-5.3)，该模型无法关闭思考。参数提取和纯函数计算流程保留。

`tests/test_runtime_document_flow.py` 使用真实 Qdrant 本地引擎和临时 SQLite 验证隔离与删除，模型流和故障由可控替身模拟，不操作用户云端资料。2026-10-09 另用自建临时验收文档实测 Qdrant Managed Cloud 上传、浏览和删除，向量由 1 条降到 0 条；临时文档和所属对话已清理。

扩展方向：增加人工核验的真实咨询样本、评估引用与答案准确性；需要多人实际使用时再替换演示鉴权、细化配置权限；政策更新规模扩大后再考虑更完善的任务管理。

## 常见问题

- 页面能开但对话返回 503：打开 ⚙，补齐模型 ID、API Key、Base URL；服务商必须提供兼容 OpenAI 的接口。
- 自定义 Token 后访问失败：在 ⚙ 弹窗填写与 `.env` 对应的访问 Token，再保存；API Key 是模型密钥，访问 Token 是本项目鉴权凭证。
- 联网无结果：检查本机能否访问 Bing、代理设置和关键词；代码有 HTTP 状态校验、超时和无结果提示，可通过 `WEB_SEARCH_URL` 覆盖搜索地址。结果为空不代表模型已查证最新政策。
- RAG 检索不可用：检查 Embedding 密钥、Qdrant 地址、网络和 `VECTOR_SIZE`。更换向量模型时必须保持原索引维度一致；已有文档需重新上传，避免混用不同模型的向量。
- PDF 提示缺少 `pypdf`：按快速开始安装 `requirements.txt`；原开发环境未安装该运行依赖。
- 图片/扫描 PDF OCR 为可选能力，按“上传与 OCR 环境”补齐 PaddlePaddle、PaddleOCR、官方模型及 Poppler。本机图片与扫描 PDF 已真实验收；缺少运行环境时会返回明确错误，CPU OCR 仍可能等待约一分钟或更久。
- `pass`/TODO 有一部分是抽象接口、开发笔记和扩展入口；`/api/tax` 明确为预留接口，不用于本次演示闭环。
